# GUI 验收 Checklist（acceptance）

- 阶段：acceptance；触发：改动 renderer / 侧栏 / 设置面 / 布局 / 右栏或任何界面判据、移动入口后；发布前跑打包态/真机腿；Owner：改动 author 出证据，评审复核；真机项由验收人执行；Timebox：机械 A ≤15 分钟；机械 B / 目检 ≤1 小时；打包态真机另计（按 §4 分组）
- 退出标准：机械腿无 FAIL（INFO 逐条解释）；目检逐条一句结论（含「未判」）；打包态/真机项有可复核证据；自动化入口：`pnpm run acceptance:gui`、`node scripts/gui-acceptance/drivers/run.mjs --flavor native --require-assembly --web-dist packages/desktop/dist/web`、`pnpm run acceptance:mobile`（ARCHIVED）；证据：PR 附 `gui-live-report.md`（或 `.json`）与 `gui-walkthrough-report.json` + 关键截图；未判项显式登记

> 本清单**不是**判据副本：判据权威在 `docs/design/`（契约）、[`../../progress/STATUS.md`](../../progress/STATUS.md)（开放工程项）与本清单 §4.2（打包态/真机验收项）；本文件只固定流程——跑什么、看什么、留什么证据；判据要改就改 design/STATUS。工具箱 [`scripts/gui-acceptance/`](../../../scripts/gui-acceptance/README.md) 的说明、已登记容忍与边界见其 README；放宽容忍先改那里，不在工具箱里猜。范围：现行 = `--flavor native`（默认）与 `--live`、Swift 真机/目检；Electron CDP 腿（`--dev`、`--dev --flavor electron`、`--attach` 的 Electron 档、`acceptance:mobile` 的 CDP 驱动）**冻结归档、不进默认验收**，复活后按原表执行（见 [`../../progress/electron-frozen.md`](../../progress/electron-frozen.md)）。

### 4.3 运行期装载补丁探针（打包态）

先决：打包态实例启用实验性 chat-import（插件页 More → 实验性插件），按插件页提示重启/等图刷新后重载页面；每步记「操作 → 观察到什么 → 证据路径」。（步骤 5–7 不需要该先决。）

1. **eval 可用性**：主窗口页面控制台执行 `new Function('return 1')()`，期望 `1`；抛 `EvalError` / CSP 拒绝 ⇒ 记「CSP/eval 不支持」并阻断后续（本探针面 = design 09 §4 的 classic-script 与 CSP `'unsafe-eval'` 前提，与锚点无关）。
2. **上传路由**：侧栏 New Session 行点导入钮、选 <300 MiB 的导出 ZIP；DevTools Network 断言 `POST /api/i/<源 id>/api/deepseek-chat-import/archive?workspaceId=…` 返回 200 且 `application/x-ndjson`（若干 progress 行后 1 条 outcome 行）。负向对照：控制面根 `POST /api/deepseek-chat-import/archive` ⇒ 404 JSON；>300 MiB ⇒ 413。
3. **served 文本一致性**：经代理取该实例 `GET /api/i/<源 id>/plugins/??@deepseek-ai/dsh-deepseek-chat-import/client.js&rev=…` 的响应文本，与 `packages/desktop/vendor/dsh/node_modules/@deepseek-ai/dsh-deepseek-chat-import/lib/client.js` 按同一 serving 变换（剥 trailer / 补换行）后比较 sha256（变换实现单源 = `verify-runtime-plugin-patches.mjs`；未变换字节直接比 sha 不成立）。
4. **失败分类**：① 步骤 1 失败 ⇒ eval/CSP 面；② 连接页出现 `bundle-load-failed` 且诊断点名补丁 `reason`/`anchors` ⇒ 锚点或 URL 形态漂移，按 design 09 §4 更新补丁表；③ 上传 404 ⇒ 补丁未生效或前缀错误（先核步骤 2 的 URL）；④ 413 ⇒ 上传超代理上限（登记 512/300 MiB 偏差，不属本机制失败）。
5. **文档预览本地图片前缀（docpreview 补丁）**：两来源（local + SSH 各一）各放 `/tmp/t1-preview/{README.md,diagram.png}`（README 只含一行相对图片引用，两张 PNG 字节不同）。分别打开右栏文档 tab，Web Inspector 取两个 `<img>` 的 `src`：期望前缀分别为 `/api/i/local/` 与 `/api/i/<ssh-id>/`，`path` 查询相同；分别 `fetch` 两 src → 200 且 sha256 各自等于源文件。负向：`fetch('/api/file?path=…')`（无前缀）⇒ 404 `{"error":"not_found"}`。
6. **degrade 启动**：受控单实例——只打开该来源、确保它第一个装载 documentpreview（其它已 pinned 来源暂不 boot；否则会经 first-load-wins 复用已补丁 factory 而假红）。把本地实例切到与 pin 不同的运行时线（或接一台**已含该包**但 bundle 文本与 pin 漂移的 dsh 远端并让其先装载）→ 期望壳正常启动（无失败覆盖层）、右栏图片保持坏（alt 文本）、Console 有 `degrade-unpatched` 判词；出现 `bundle-load-failed` 覆盖层 = 红灯。**旧远端臂（未证实，登记待远端实证）**：远端 dsh 旧于该包引入的版本时该行**整行缺席**（无右栏文档 tab、无 degrade 判词，壳正常）——该臂不得按 degrade 期望判红。
7. **回归**：外链 https 图片仍正常；禁用 documentpreview 行后无文档 tab、无 `/api/file` 请求；PDF/Excel/HTML 懒块仍可打开（包内 chunk 未被拦截）。
8. **gateway 形态 smoke**：gateway 页面（官方前端、单实例）启用该 bundle 后按步骤 2 上传一次；URL 无 `/api/i/` 前缀（root 直达），期望同样 200 NDJSON（验证「gateway 不需要该机制」的契约）。
