## [0.4.6-beta.2] - 2026-11-27

### Changed
- **The bundled dsh baseline rises to 0.2.3-alpha.2 (4b399c39)** — the rc.3 → alpha.2 delta is concentrated in package version bumps plus a few comment-only sources (only four real source files change under `src/`: three comment-only TS files and one python package initializer), and the alpha.2 runtime closure fixes the `EntryValidationError` export break in alpha.1. Chamber adaptation lands in the same batch: host-synced client config for covered/extra rows, the `ui-session-status` first-screen row with its self-mounted HMR remote, HMR live sync as a per-instance `pluginEvents` Remote stream, retirement of the `ui-theme` patch, consolidated Office assets with the pypdf payload, disabled remote-connection/forge-gitlab rows, the official worktree entered record, and the sidebar/layout/seed fork replays (design 02/09/19; current values are single-sourced from `harness.commit` and `packages/desktop/vendor/dsh/pnpm-lock.yaml`).
- **The Node engine range tightens end to end to `^24.22.3 || >=26.13.1`** — gateway `engines`, the installer version floor (parsed as major.minor.patch instead of a fixed 24.9), and the `verify-pin-alignment` cross-checks (root engines, gateway, installer constant, upstream vendor engines, and the `.nvmrc`/payload/workflow `node-version` mirrors) align in one batch and close the old Node 22/24.9 loopholes (design 18; README, DEVELOPMENT and the remote-instance docs follow).
- **Connection lifecycle, intent ownership and the source roster are hardened as one generation** — local start/stop/restart/exhaustion/cancel legs go through one process-group exit proof plus generation health probes, and an unproven writer fails closed (`stop()` returns 409 and never publishes restart-exhausted); manual disconnect is owned by the sidecar for one app session (row-local metadata written atomically, compensation-safe, refused on degraded rosters) and only explicit IPC changes the intent; ready/re-verify/refresh/revoke share one commit entry (accept-then-publish, health probes never re-register, failed auth fails closed, incarnation and transport-generation tombstones); the separate gateway-sync mirror is removed; one committed roster change set drives transport/exec/forward/seed revocation and source retirement, with logical source identity = kind+host+remotePort (an entry-level identityScheme migration keeps existing proofs); manual disconnect becomes session-scoped, mechanism switches keep source history and remount the shell, and remote dsh HTTP 401 maps to the instance-auth hint (design 05/18/21/26).
- **Notifications, attention and completion delivery follow app activation and background completion** — notification focus derives from app activation, background session completions still deliver while the page is not visible, and durable notifications no longer drop on partial rosters; the renderer gains the v3 attention-model notification/attention gates (design 06, design 19).
- **Docs and gates consolidate** — the documentation set slims down and package README contracts land, status records leave code and test comments, CI runs the seed and gateway type checks in typecheck mode, and upstream browser files are verified against the vendor tree (documentation rules and gate-surfaces as the single source).

- **Right-panel open/close no longer reflows the conversation every frame** — docked open/close lands the centre-column track in one frame (the panel keeps its own 300ms transform slide; fullscreen entry/exit semantics are unchanged) instead of easing for 300ms. Running-page A/B (injected instant-track proxy): open p95 62–105ms → 11–17ms, close 111–119ms → 10–15ms, with the ≥50ms-frame and blocking time dropping in step; the one remaining landing reflow and the left-sidebar track are out of scope (design 06 §13, TODO §3.9).
- **The right-panel browser guest spends less on scroll and occlusion detection** — unrelated scrollers (chat and friends) no longer trigger placeholder geometry reads; the occlusion hit test is throttled to ≤10Hz with a trailing catch-up (placeholder geometry still measured every frame), and the overlay-candidate list refreshes on the 100ms re-check cadence with a forced first-frame refresh. Guest position/occlusion/hide semantics are unchanged (design 28 §4.1).
- **Notification-ledger memory and writes are bounded** — the three durable tables (`notifiedRuns`/`pending`/`outcomes`) keep the same per-source window in memory and on disk (the latest 500 sessions, 500 goals for outcomes), so long-lived sources no longer grow with session churn; the page-local watermark no longer counts as durable write evidence and pruning only persists when a durable table row is removed, removing needless full serialisation and writes (design 19 §3.2.4, §3.2.7 ⑩).
- **At most one completion banner per task (the goal is exactly one)** — a completion candidate now waits while the parent turn ended but subagents still run, and is settled silently once they finish (the banner belongs to the wake turn); if a strictly later host `turn/end` identity was absorbed while waiting, it is delivered once under that identity. This removes the duplicate banner pair of the dispatch turn plus the wake turn (design 19 §3.2.3 G4/#13, §3.5).
- **Gateway sources now carry running-subagent evidence too** — the session-state mirror adds three additive optional fields (running descendants, lineage-verified bit, fail-closed retained bit): an old gateway omits them and the decision falls back to presence/unknown (never busy), while an old desktop reading verified && presence > 0 is correct exactly where the running count is positive; upgrading both ends converges (design 17 §10.7, design 19 §3.5 I-12).
- **Facts evidence falls back to the lineage classifier when the shell row has no activity evidence** — facts-only sources (no shell) previously never deferred a completion; the decision and presentation planes now share one three-valued classifier, and the running-descendant count joins the facts row signature, so a busy→idle change is published instead of being swallowed by content dedupe (design 19 §3.5 I-12).
- **The sidebar checkout-row health badge retires** — the chamber-only in-row worktree-invalid / status-unknown chip is removed: the upstream worktree service exposes no such health surface, so the chip merely restated Git probe failures as row state; removal and targeting stay with the action gate and error copy (design 06 §3.2, design 08 §3.2).
### Fixed
- **Chamber host seeds move to the profile fallback layer** — seeds no longer live in the pnpm-managed `profiles/web/node_modules`, so a `dsh plugin add/remove` relink can no longer move client-graph/git-worktree/archive-cleanup/open-in into `.ignored`; every resolve deletes the legacy copy first and re-seeds the fallback, and the desktop local-plugin probe plus the acceptance fixture read the fallback layer (design 09 §3.5, design 02 §2.6).
- **The page-boot store double registration** — the seed already registers `@deepseek-ai/dsh-client-store` when the module system is created, and the composite registered the same id from `COVERED_FACTORIES`, which raised `duplicate factory registration` and aborted the remaining covered factories; the store stays in the dedupe set only, `SEED_PLATFORM_IDS` joins the unsatisfiable-dependency predicate, and the design plus both test directions land in the same batch (design 09 §3.2/§3.5).
- **Source builds lost `process.platform`** — the bundled loader reads `process.platform` in `EntryTree.import`, while Vite folds only `process.env.*`, so every loader entry threw `ReferenceError` and stayed fiberless; the page build defines the same key as upstream `apps/web`, with a regression lock that a commented-out define does not satisfy.
- **Boot conflicts and load failures merge into one report**, durable notifications survive partial rosters, source proofs persist across host restarts, stream-state source epochs stay monotone across retirement, and acceptance entries plus frozen-artifact freshness are repaired.
- **The sidebar skips used titles when naming forked sessions**, and document preview images resolve through each entry's base path.
- **macOS shell** — the phase-plan test passes the active fact, and design 25's crash-disassembly note stays in lockstep with its XCTest lock.

- **The blank new-session ghost slot now really disappears at its deadline** — the local expiry clock only updated its own state and never reached the memoised section render, so the hidden placeholder (a 26px layout slot) lingered until the next projection; the deadline is now published through a section-context version and the row stops rendering immediately, with the slot key scoped by source (cloned instances sharing a session UUID no longer cross sources) (design 06 §2.2).
- **The right-panel browser guest refreshes its first-frame occlusion candidates when mounted inside the page's first 100ms** — the candidate cache clock no longer treats never-queried as just-queried, and a remount resets it too (design 28 §4.1).
- **A page-local-only notification advance no longer schedules a full durable write** — page-local watermark and volatile-track changes no longer count as persistence evidence, and `prune` only persists when a durable table row is removed (design 19 §3.2.4).
- **A hidden legacy subagent row revealed by a gateway presence frame recomputes the parent evidence in the same tick** — activity / pending / cancel / already-stopped status frames all recompute, so the pre-first-baseline fail-closed window cannot read the source as idle and fire one banner early after a restart (design 17 §10.7, design 19 §3.5 ⑧).
- **Persisted completion identities are validated on load** — `completionSeq` / `absorbedSeq` are cleaned field-wise (an invalid value drops the field, never the entry), so a delayed completion still supersedes after a reload (design 19 §3.2.4).
- **An unjudgeable gateway lineage warns once per process** — a lineage that stays unjudgeable after a successful baseline no longer suppresses subagent busy evidence silently (design 19 §3.5).
- **Packaged runtimes keep skill Markdown** — payload pruning no longer deletes the Markdown of runtime skill directories, so skill docs stay readable in packaged builds.
### Docs
- Design documents and progress records update in the same batch: design 02/05/06/09/14/17/18/19/21/25/26/28, the checklists, TODO (boundary register and engineering-debt list) and the i18n record.
## [0.4.5] - 2026-11-16

### Added
- **Local Swift instances bundle the Office skills and the full primary-runtime payload** - the local Swift spawn mounts `dsh-skill-office` and `dsh-tool-workspace-dependencies` through the existing `--patch` overlay and ships the complete `primary-runtime` (node + pnpm + python) with the `office-skills` assets; render/convert/recalculate are carried by the upstream native tools `office_render` / `office_convert` / `office_recalculate`, so the app carries four skill directories (`office` / `office-docx` / `office-pptx` / `office-xlsx`). The first tool call installs the read-only payload into `<DSH_HOME>/dsh-runtimes/dsh-primary-runtime` without rewriting app files; a missing payload or asset lets the host start normally and the capability stays honestly absent. These capabilities serve local instances only: gateway and SSH remote instances do not mount them (recorded in deviations), and clean-machine/packaged acceptance is tracked by the release checklist (design 18 §4.2, design 25 §4.3/§3.2).
- **Settings → General gains a read-only Performance & Memory group (with manual release)** - the resident-source table shows each source's state (active / resident / starting / failed / released), hidden duration and DOM node estimate; the panel footer shows the most recent release source and reason, and each source gets a two-click "Release UI" action. Page JS heap and machine memory only render readings the platform actually provides and show "unavailable" instead of guessing. The group mounts only while debug mode is on, and releasing only tears down the UI shell, never instance processes, tunnels or background jobs (design 15 §D5, design 05 §4.1).
- **Sidebar panel entries of every source render from that source's own registration** - each mounted shell publishes its `sidebar.panellist` snapshot to a page-level singleton (`{id, order, label}`, unknown ids hidden), so a non-active source's header shows its own panel entries; a connected but unmounted source falls back to the fixed default set (clock). A click first activates the target source and then hands a one-shot `selectPanel` intent to that source's own shell: the intent survives across boots, its TTL starts at click time, and the target only calls selectPanel for panels it actually registered (design 05 §2, design 06 §4.3/§4.7, design 09 §3.6).
- **The Settings update entry gains a status indicator and technical details** - the Settings → Client (`__general`) update row renders an icon-only indicator in wide layouts (Tooltip plus aria label, no visible copy): `none` renders nothing, `busy` spins with `aria-disabled`, `available` shows a download glyph and `error` a red dot; a click opens Settings on the "Update" group and the status row stays the only progress surface. Failed-update rows gain a collapsible "Technical details" section (reusing the already-redacted `update.error`, no entry for empty errors); both derive from the update-store projection the page already shares (design 05 §5, design 15 §1, design 25 §7).
- **The `dsh-chamber://open` deep link wakes an existing window** - the new argument-free deep link accepts only URLs whose hostname is exactly `open`, whose path is empty or `/`, and that carry no userinfo/port/query/fragment (every other variant is loudly rejected); the sidecar hands the intent to the Swift shell through the existing brokered host, which restores/activates the existing window and focuses it. On a cold start without a window the existing deep-link buffering path applies and the intent is replayed in order after the sidecar is ready (design 16 §3.1).

### Changed
- **Bundled dsh baseline rises to 0.2.2-rc.3 (38a6a5c9)** - this release spans two upstream generations, rc.1 → rc.2 → rc.3: rc.2 is the 76-release-note interface/contract generation (official forge review surface, named multi-level SubAgent collaboration with the AgentTeam member/task panel, earlier-message loading when scrolling up plus diff rows colored by added/removed and highlighted by file language, configurable model request retry conditions/counts/waits, DeepSeek Search API as the default web search, native Gemini provider with model discovery and reasoning level, native Office tools), and rc.3 adds the `sidebar.session.action` HOC decal seat on the official New Session row and brings the experimental DeepSeek chat-import plugin; the source line, the runtime line, the three `@deepseek-ai/*` fork copies and the release anchors re-anchor in one batch (live single sources = `harness.commit` and `packages/desktop/vendor/dsh/pnpm-lock.yaml`). Chamber adaptations land in the same batch: the chamber sidebar declares and renders the `sidebar.session.action` seat the same way upstream does, the Office startup/bundle rows follow rc.2's asset surface and Config, session-stream auto-recovery re-anchors on `ISessions.binding(id)`, the chat-import upload route gets a two-anchor base patch in the plugin load seam, and the Swift shell's window drag region plus "paste and match style" align with rc.2 semantics (design 02 §3.1, design 09, design 19).
- **The right-sidebar Browser moves to a Swift-native guest carrier (one child `WKWebView` per tab)** - the 0.4.4 system-browser launcher and the v2 iframe carrier retire as a generation: every tab occurrence owns a child `WKWebView` the Swift shell holds (its own web content process, a non-persistent `WKWebsiteDataStore` keyed by (source identity, workspace key)), and the renderer keeps only the upstream address bar/history/store/title/restore/failure bar and placeholder geometry; the eight upstream UI files stay byte-verbatim behind SHA-256 locks and `BrowserPage` is the only fork-diff carrier file. The target site's XFO/`frame-ancestors` no longer white-screens and an in-site `_blank` opens a new tab in the panel (rate-limited to 6 per 60s per tab occurrence); the only behavioral difference remains the SSH reverse proxy (forward wire raised to v3, logical URL kept apart from the alias projection, tab close releases the consumer), and the desktop CSP narrows `frame-src` back to `blob:` (design 28 §1/§3/§5/§9, ADR-0004).
- **N-ctx shells become keep-all residents** - every source shell the user opened stays mounted for the page lifetime and the old "keep at most 1 hidden shell plus a 60s reclaim" mechanism is deleted; speculative shells (idle warm-up / first-screen harvest) still occupy one background slot. Release now has only explicit paths (source retirement, boot failure, 135s stall, overlay abandon, harvest eviction, manual release, a hard cap of 12, platform memory pressure), and the pressure valve samples machine-available memory every 30s (`constrained` keeps at most one most-recently-used resident shell, `critical` releases every releasable shell, two consecutive readings per tier with 250ms staggered work). The cost is recorded honestly: per-shell byte memory is unreadable in a single-renderer architecture and under `critical` an unsubmitted draft in a background shell can be lost with its release (design 05 §4.1).
- **The Electron flavor is frozen and archived; macOS Swift is the only shipped flavor (breaking, distribution scope)** - the Electron main entry/edges/preload move into `packages/desktop/electron/` as an archive (files kept and revivable; scope and revival checklist in `docs/progress/electron-frozen.md`), and the Electron packaging/update legs, the Windows/Linux desktop legs and Electron-only tests are frozen; releases produce only Swift and gateway artifacts, so macOS Swift users are the only desktop users still receiving this version (macOS Electron and Windows/Linux users stay on 0.4.4). The shared sidecar business core, host contracts and code shared with the Swift leg stay maintained; revival needs the scope reopened (AGENTS.md, design 25).
- **The update channel becomes a user preference: subscribe to beta updates from Settings** - the version suffix no longer decides the channel; native release builds inject both the stable and the rolling beta appcast URLs at assembly time, and at runtime the Settings → General "Receive beta updates" switch (or `DSH_CHAMBER_UPDATE_CHANNEL=beta`) chooses between them, defaulting to stable - so a beta build also follows the stable channel by default and a beta subscription survives version changes once enabled. In older builds that injected no dual-channel feed the switch is disabled and explains why (design 25 §7, design 15 §2).
- **Bundled runtime pins align with upstream (Node 24.21.0, pnpm 11.28.5)** - the primary-runtime payload's Node rises to 24.21.0 (the archive sha256 is taken verbatim from the upstream pin lock) and the embedded pnpm to 11.28.5; the payload lock, lockfile and third-party notices refresh in the same batch. User-visible surface = the bundled Node/pnpm versions and the runtime version row.
- **Hidden or occluded windows stop advancing foreground rendering, polling and compensation** - the Swift shell dispatches `dsh-chamber:shell-visibility` to the page on visibility changes (`{visible, occluded}`, covering orderOut/minimize/Cmd+H/losing key/occlusion and another visible Space/restore/navigation replay; identical values are deduplicated and a dispatch failure is loud without blocking), and the page combines it with page visibility into the unified foreground phase gate `background-phase.ts#shouldRunBackgroundPhase`: polling, the render watchdog, keep-awake, notification suppression, the resident-shell memory pressure valve and recovery compensation (a 250ms dedup window) all go through that gate, and a visible-and-unoccluded recovery edge compensates once through the same window. keep-awake tightens to "setting on and window visible" before holding `ProcessInfo.beginActivity`, and the native drag-pasteboard poll and render watchdog also stop (design 25 §5.7, design 14 §D1).
- **Duplicate fact frames and per-second jitter are eliminated** - the device-fact observers on both the gateway and the direct mux sides now dedupe content summaries at a single `emit()` exit: frames that carry only an advancing cursor or lastEventAt while the row wire content and source-level rendering/decision inputs (hostState/serviceable/mode/stale) are unchanged are no longer published; the rendering field `factAt` in the runtime report signature is quantized to 1s buckets (the raw `factAt` still enters reports and evidence anchors verbatim). User-visible surface = fewer per-frame badge and sidebar re-renders and lower App-commit and battery cost in multi-source pages, with the identity/projection signature paths converged in the same batch (design 14).
- **A multi-shell page keeps one copy of the theme sheets and the icon sprite** - `ui-theme` previously installed its eight theme stylesheets and icon sprite once per instance shell (hidden shells never uninstalled them); the patch now hangs the registry on the document behind `Symbol.for` so it is shared across shells and removed only when the last owner's refcount drops, with a shared sprite markup map and identical-theme reapplication as a no-op (a cross-shell `theme/change` is last-write-wins). Document-level stylesheets and SVG symbols no longer grow linearly with the shell count (design 09 §3.6).
- **First-screen size drops because simple-icons moves to its ESM entry** - the vendor icon table previously pulled every icon into the composite first-screen graph through the CJS entry; vite now resolves the bare `simple-icons` specifier to the package-declared `exports["."].import` ESM entry before general `require` resolution (`resolveSimpleIconsEsmEntry`, failing loud when the entry is missing or points at a nonexistent file). The same-worktree A/B measured a -60.8% raw entry size and -72.1% gzip in the chamber entry; only that entry changes and icon rendering is unchanged (the budget thresholds were not re-based on this drop).
- **Chat scroll geometry, sidebar row motion and instance-proxy parsing no longer recompute every frame** - `ui-chat` scroll delivery collapses to one geometry read per frame (`onScrollEnd` flushes synchronously first, detach cancels, synchronous fallback without rAF); the sidebar's hover-gated subtree scan only runs when the row-key sequence changes and the FLIP row-motion animation sets a 250ms minimum gap between start batches, gating `data-hover-gate` only on rows moving this frame that were not under `:hover` during the scan. In the same batch, WebSocket frame scanning is no longer byte-by-byte: a non-CLOSE frame skips its payload in one step (cross-chunk frames only subtract the remaining length), while CLOSE still takes the byte path for the close code.
- **Native shell window geometry aligns with the upstream viewport** - the content area uses the upstream desktop viewport of 1280×792 with a 520×572 minimum (the upstream frame of 1280×820 / 520×600 minus the 28pt title bar), with `WindowMetrics` as the single size source and the traffic-light/title-bar relayout in the same batch (design 25 §5.6).
- **Background update checks run once on foreground/wake, and installing exits full screen first** - the existing noteActivity criteria (phase gate plus at least `SUScheduledCheckInterval` (600s by default) since the last completed check plus a 60s merge window) now also trigger one `checkForUpdatesInBackground`, with the check period and backoff unchanged; "Restart and install" prepares a full-screen exit before running (single criterion = the shell's full-screen flag, waiting at most 5s) and returns the stable `fullscreen-timeout` code for the page to offer a retry (design 25 §7).
- **Checkout rows and the worktree dialog converge** - the checkout row's "modified / locked / unknown" state appears only while the row's actions are revealed (the pill moves into the host-owned `data-git-occupant` container, leaving a neutral branch glyph and count badge at rest); the new-worktree dialog reads branch candidates live on open through the new read-only `gitWorkTree/branches` (same gate stack as `previewCreate`, explicit errors rather than an empty array, falling back to `snapshot.branches` on a 404 from an old host); and new-session/`gitWorkTree/enter` triggers force one session-list reread, so a new id reaches the shell in one RTT and the reveal settles immediately (design 08 §2.1/§4.1).
- **Managed hosts inherit the user's login-shell environment (rc.2 alignment)** - Dock/Finder launches only inherit the session manager environment; both desktop entries now perform one process-level read (the account's login shell → `/bin/zsh` → `/bin/bash` → `/bin/sh`, running `<shell> -ilc` around `command env -0`), and the shell's values override inherited ones except probe environment keys, probe session variables and the `DSH_*`/`ELECTRON_*` namespaces. The control plane and window construction do not await it; a single candidate gets 10s by default, timeouts/aborts move to the next candidate, and total failure falls back to the inherited environment with per-line warnings; gateway/standalone do not read it (design 02 §3.1).
- **System logout/shutdown is no longer blocked by the quit confirmation** - `NSWorkspace.willPowerOffNotification` sets the sessionEnding gate on arrival: the first line of `applicationShouldTerminate` exempts that gate and lets the system proceed instead of showing the quit confirmation or making the system wait on `.terminateLater`; `didBecomeActive` resets it afterwards, and the normal quit confirmation and in-flight decision merging semantics are unchanged (design 14 §D2).
